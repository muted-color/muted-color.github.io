# 연구 노트 편집 기준

- Gemma4 비교 글과 ESM2/LoRA 글의 담백한 연구 노트 톤을 따른다. 개인 서사, 기사식 과장, 튜토리얼식 선언보다 평가 문제와 해석 조건을 먼저 고정한다.
- 초반에 연구 질문과 빠른 결론을 제시하고 바로 조건과 한계를 붙인다. 긴 실험 글은 앞쪽에 `## 요약` 또는 대상 언어의 동등한 제목을 두고 4–6개 항목으로 핵심과 caveat를 정리한다.
- 목차는 시간 순서보다 증거의 역할로 구성한다. 준비 조건이 둘 이상이면 `Experimental Setup`, 연속 결과가 둘 이상이면 `Results` 아래에 묶는다. 재사용 가능한 진단 기준·해석 틀은 별도 최상위 섹션으로 둘 수 있다.
- 단락은 관찰, 해석, 주의점의 연결을 보여준다. 모든 문장을 같은 틀로 반복하지 않는다. 헤딩은 명사형·주제형을 우선한다.
- 모델·데이터셋·benchmark·약어가 처음 나올 때 필요한 최소 정의를 문장이나 짧은 blockquote로 제공한다.
- 글에서 실질적으로 분석하는 논문 유래 방법은 첫 설명에 대표 저자 `et al.` 또는 기관명, 방법명, 인용을 함께 둔다. 범용 기법과 부수적인 언급에는 강제하지 않는다.
- 표와 수치에 비교 조건, 지표 방향, 읽는 법과 한계를 설명한다. 자동 지표, judge 지표, runtime, variance를 서로 다른 근거로 다룬다. 약한 신호, 반례, seed/split 변동과 실패 가설을 숨기지 않는다.
- Appendix는 benchmark 조건, method glossary, metric caveat 등 공개 독자가 해석·재현에 필요한 내용을 우선한다. 내부 운영 경로 목록으로 대체하지 않는다.

## 용어

| 피할 내부 표현·과장 | 의미에 맞는 표현 |
| --- | --- |
| `same-contract`, `frozen question` | 동일한 평가 조건, 고정된 평가 질문 |
| 설명 없는 `residual` | 남는 오류, 구조적으로 남는 한계 |
| `Stage 0/1`의 반복 | 초기 가능성 점검, 본 평가, 후속 비교; 필요한 내부 명칭은 괄호로 1회 |
| `opened`, `opening`, `benchmark opened` | 의미 있는 성능 차이가 확인됐다, 비교할 가치가 있는 평가 문제 |
| `closeout`, `line closed` | 현재 단계의 결론, 현 설정에서의 마무리 |
| 근거 없는 `winner`, `최종 모델` | 현재 기준선, calibrated reference, primary score 기준 조합 등 실제 역할 |
| 개발 전인데 `새 모델`을 제안한 듯한 표현 | 방법 비교, 평가 문제, benchmark 설계, 신호 조합 |

단일 승자나 강한 개선이 입증됐다면 근거와 조건을 함께 제시할 수 있다. `압도적`, `완벽`, `명백히 SOTA` 또는 정형적인 심사평·주의 문구로 근거를 대체하지 않는다. 새 용어는 숫자와 표보다 먼저 설명한다.
